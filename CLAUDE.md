# Claude Configuration & Guidelines

## 1. Project Overview
**Application**: App-BDJ-Back (Node.js Backend)
**Stack**:
- **Runtime**: Node.js (v20+)
- **Framework**: Fastify
- **Language**: TypeScript
- **Database**: PostgreSQL (Driver: `postgres.js`)
- **Validation**: Zod (`fastify-type-provider-zod`)
- **Authentication**: JWT (Jose) + Argon2
- **Tooling**: Biome (Lint/Format), Vitest (Test), Docker

## 2. Architecture
The project follows a **Feature-Based** (Vertical Slice) architecture.
Everything related to a specific domain (feature) is grouped together.

```
src/
├── db/             # Database connection setup
├── plugins/        # Shared plugins/middleware (Auth, etc.)
├── routes/         # Feature modules
│   ├── auth/       # Auth Feature
│   │   ├── schema/ # Zod Schemas for Auth
│   │   └── auth.routes.ts
│   ├── questions/  # Questions Feature
│   └── ...
└── index.ts        # App Entry Point & Route Registration
```

## 3. Conventions

### Naming
- **Files**: `camelCase` (e.g., `auth.routes.ts`, `auth.schema.ts`).
- **Variables/Functions**: `camelCase`.
- **Database Tables/Columns**: `snake_case`.
- **Zod Schemas**: PascalCase, prefixed with `Z` (e.g., `ZUser`, `ZLoginResponse`).

### Imports
- **Extensions**: Always include `.js` extension for local imports (ESM requirement in TS).
  ```typescript
  import sql from "../../db/db.js"; // Correct
  ```

### Database
- **Schema Management**: SQL scripts in `docker/initdb.d/`.
- **Changes**: For now, modify the SQL files and restart the container to reset the DB.
  ```bash
  pnpm docker:restart
  ```

### Code Style
- Use **Biome** for linting and formatting.
  ```bash
  pnpm format
  ```

## 4. Development Workflow

### Adding a New Feature (Checklist)
1.  **Database Design**:
    -   Create or update SQL file in `docker/initdb.d/`.
    -   Run `pnpm docker:restart` to apply changes (Warning: Data loss).
2.  **Schema Definition**:
    -   Create `src/routes/<feature>/schema/<feature>.schema.ts`.
    -   Define Input/Output schemas using Zod.
3.  **Route Implementation**:
    -   Create `src/routes/<feature>/<feature>.routes.ts`.
    -   Implement handlers using `postgres.js` for DB queries.
    -   Use `sql.begin` for transactions if multiple queries are needed.
4.  **Registration**:
    -   Import and register the new route in `src/index.ts`.
5.  **Verification**:
    -   Test the endpoint manually or via unit tests.

## 5. Design Patterns
-   **Auth**: Bearer Token (JWT) + Refresh Token. Use `authenticate` hook.
-   **Validation**: Strict Zod schemas for `body`, `params`, `querystring`, and `response`.
-   **Error Handling**: Utilize Fastify's default error handling + Zod validation errors.

## 6. Services
-   **Notifications**: Centralized service (`src/services/notifications.service.ts`) to handle creating notifications.
    -   `createNotification`: For single user notifications.
    -   `notifyAllUsers`: For broadcasting to all users (with optional exclusions).
    -   Handles database insertion and can be transaction-aware.
